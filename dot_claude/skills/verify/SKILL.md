信頼できる文献を参照して、以下の内容を精査してください。

## 対象
$ARGUMENTS

引数がディレクトリの場合はその配下の全ファイルを対象とする。
引数がない場合は、エディタで現在開いているファイルを対象とすること。開いているファイルもない場合は、ユーザーに対象を確認すること。

## 手順
1. 対象の内容を正確に把握する
2. Context7、DeepWiki、Web検索などを活用して信頼できる情報源から裏付けを取る
3. 事実と異なる点、曖昧な点、古い情報がないか確認する
4. 文書内に引用・出典・URLがある場合は以下も確認する
   - 引用元が実在し、主張の裏付けとして適切か
   - URLがアクセス可能か（WebFetch で確認）
   - 出典の表記形式が文書内で統一されているか
5. 精査結果を以下の形式で報告する

## 判定の決まり
- 「誤りまたは要修正」に置けるのは、信頼できる出典（公式サイト、一次資料、規格、公式ドキュメント、報道。Wikipedia は補助）の URL を添えられる場合だけにする。出典が取れなければ「未確認」に置き、訂正案は書かない。訓練データの記憶だけで訂正しない（誤った訂正は、指摘しないより害が大きい）
- 2025年以降の事柄は記憶にない前提で、必ず検索する。検索は日本語と英語の両方で行う
- 文書中の URL は WebFetch で開き、届くかと、主張を支えているかを確かめる
- 逐語の引用は、引用元の原典で確かめる。原典で確かめられないものは「未確認」にし、書き手が原典で確かめるよう添える。孫引きは根拠にしない
- 体験・感想・解釈は対象外にする。ただし解釈の前提になっている事実が誤っていれば指摘する
- 「未確認」には、どこを探して見つからなかったかを書く
- 検索ツールが上限に達したら、`~/.claude/mcp-guidelines.md` の判断順に従って別の検索・取得の手段に切り替える

## 報告フォーマット
カテゴリごとにまとめて報告すること。
各指摘には全カテゴリを通じた通し番号を、接頭辞 F を付けて振ること（#F1, #F2, #F3, ...）（ほかのスキルの指摘と混ぜても種類を見分けられるようにするため）。
各指摘の先頭には該当するファイル名と行番号を `file_path:line_number` の形式で記載すること。
報告は Markdown として表示される。各指摘は下の形のとおり `- #F番号 …` の項目の下に各欄を入れ子の箇条書きで並べ、区切り線（`---`）は使わない（文の直後の `---` は直前の行を見出しに変え、箇条書きにしない行は改行が消えて一行につながるため）。

### 正確な点
裏付けが取れた内容を報告する。指摘ごとに以下の形式で記載する。

- #F番号 `file:line`
  - 内容: 内容の説明
  - 出典: 情報源

### 誤りまたは要修正
事実と異なる点を報告する。指摘ごとに以下の形式で記載する。

- #F番号 `file:line`
  - 内容: 内容の説明
  - 正: 正しい情報
  - 出典: 情報源

### 未確認
裏付けが取れなかった点を報告する。指摘ごとに以下の形式で記載する。

- #F番号 `file:line`
  - 内容: 内容の説明

### 引用・出典の問題
文書内の引用・出典・URLに問題がある場合に報告する。問題がなければこのセクションは省略する。

- #F番号 `file:line`
  - 該当箇所: 引用・出典・URLのテキスト
  - 問題点: （リンク切れ / 引用元が主張を裏付けていない / 出典表記の不統一 など）

### 補足
追加で知っておくべき情報（バージョン差、非推奨など）を記載する。

### サマリー
最後に以下を記載する。

- **件数**: 正確 X件 / 誤り・要修正 X件 / 未確認 X件 / 引用・出典 X件 / 補足 X件
- **総評**: 精査全体を通じた所見を1〜3文で述べる（信頼性の評価、特に注意すべき点など）。
