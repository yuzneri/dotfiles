直前の /proofread の結果から、指定された指摘番号について修正してください。

## 対象
$ARGUMENTS

## 手順
1. 指定された指摘番号（例: #3, #1,#4）の内容を確認する。番号が指定されていない場合はすべての指摘を対象とする
2. 各指摘の修正案に従い、文書を修正する
3. 表記揺れの指摘については、推奨された表記に文書全体を統一する（指摘箇所以外にも同じ揺れがないか確認する）
4. 修正内容を報告する

## 注意

### 適用の基本
- 修正案をそのまま適用することを基本とするが、前後の文脈に合わない場合は調整する
- 表記揺れの統一では、指摘された箇所だけでなく文書全体を対象に統一すること。ただし引用文・台詞・書名や作品名・コードと識別子・仕様書や画面の項目名は原文のまま残す
- 技術原稿の修正は `/proofread` の「文章規範（整形・表記）」と `/advise` の「文章規範（内容・論証）」の両方に沿わせること（一文ごと改行、ダッシュ・中黒の不使用、太字と「」の使い分け、LLM っぽい表現を持ち込まないなど）

### 意味を保つ
- 修正前後で次の4点を変えないこと。主張（何を言っているか）、比重（何を主とし何を従とするか）、言い切りの強さ（断定・推量・可能性に加え、許可「〜してよい」・能力「〜できる」・義務・保証「必ず〜する」）、文の働き（評価・説明・依頼・予定に加え、伝聞「〜とされる」・意見「〜と思う」・例え・反語・仮定）。修正案がこのいずれかを動かす場合は、文脈に合わせて調整するか未対応に回す
- 上の「変えない」は、指摘が直すよう求めた点には当てはめない（二重否定を肯定にする、文末の立場をそろえる、擬人化した主語を改める、術語を定着した語に置き換えるなど）。次の「足さない」の規則はこの限りでなく、いつでも当てはめる。文書にない動作主・数値・条件が要る指摘は「書き手に確かめたい点」に回す
- 言い切りの強さは互いに入れ替えない。「〜してよい」を「〜できる」にしない、「〜場合がある」を消して言い切らない、元にない「必ず」「〜できる」を足さない（「〜することができる」を「〜できる」にするのは同じ強さなので構わない）。仕様の記述では、この違いがそのまま仕様の違いになる
- 係り受けや修飾の曖昧さを直すとき、意図した読みが前後から決まらなければ一つに決めず「書き手に確かめたい点」に回す

### 足さない
- 元の文と前後にない動作主・名詞・条件・数値・例・術語を足さないこと（指摘された語を定着した語に置き換えるのは、足したことに数えない）。指示語を名詞に戻す、省かれた目的語を補うのは、指す先が前後の文に明示されているときだけとする。補えない情報は本文で創作せず「書き手に確かめたい点」に回す
- 元の文にない因果・評価・一般化・勧めも足さないこと。並べただけの事実を「〜した結果」「〜ことで」でつながず、関連を因果に強めない。人や役割の語と対象の範囲も狭めない（「担当者」を「運用担当者」にする、前後の文の「一部の〜」を別の文へ持ち込む）

### 直し方ごとの注意
- 語句や文を削る・まとめるときは、削る側にしかない数値・条件・例外・期限・バージョン要件と、「未確認」「未定」の断りを、残すか残す側へ移す
- 冗長な「こと」の外枠を外すときも、義務・決定・経験・頻度（〜する必要がある、〜することになった、〜したことがある、〜することがある）は残す
- 長い文を分けるのは、前後の関係（手段・理由・順序・対比）を後ろの文の接続表現（「そのため」「一方で」など）で残せるときだけとする。目的や理由が文末の結論にかかる文（「〜するために〜します」）は、分けると向きが変わるので分けない。分ける・つなぐ・語順を変えるときは、主題（〜では）と条件・否定のかかる範囲を保つ
- ダッシュを外して前後を一文につなぐとき、前にある理由や条件（「〜ため」「〜なら」）のかかる範囲が後ろまで広がるなら二文に分ける
- 見出しから区切り線やコロンを外して短くするときは、外した条件・警告・結論を本文に残す
- 文末をそろえるときは、立場に合わない文末だけを直す。強さを上げない（勧めを「〜しなければならない」にしない）、主語を足さない、文をつなげて同じ文末の数を減らさない

### 仕上げ
- 修正は一回で済ませる。指摘を消すためだけに言い換えを重ねない
- 修正後に元の文と見比べ、次を確かめる。元にない語が増えていないか、必要な語や前提が消えていないか、否定の有無・誰が誰に何をするか・範囲と条件（だけ、一部、〜の場合だけ、または／両方）・数値と時期（約、以上、未満を含む）が変わっていないか、文末の種類が意図せず変わっていないか、箇条書きを地の文にした際に評価や義務（「〜が大切です」「〜する必要があります」）が足されていないか。数字の全角半角や桁区切りのような表記だけの書き換えは変化に数えない

## 報告フォーマット
報告は Markdown として表示される。各指摘は下の形のとおり `- #番号 …` の項目の下に各欄を入れ子の箇条書きで並べ、区切り線（`---`）は使わない（文の直後の `---` は直前の行を見出しに変え、箇条書きにしない行は改行が消えて一行につながるため）。

### 修正内容

- #番号 カテゴリ（誤字脱字 / 表記揺れ / 句読点・記号・全角半角 / 不自然な日本語 / 読みにくい文 / 段落の形式 / 文体・文末 / 文章規範（整形・表記））
  - 箇所: `file:line`
  - 変更前: 修正前のテキスト
  - 変更後: 修正後のテキスト

### 未対応の指摘
修正を見送った指摘があれば、番号と理由を記載する。

### 書き手に確かめたい点
修正に必要な情報が文書から読み取れなかった点、接続先や文書の立場を決めきれなかった点があれば、最大3点まで問いの形で記載する（4点目以降は「未対応の指摘」に理由を添えて回す）。なければ見出しごと省く。
