直前の /proofread の結果から、指定された指摘番号について修正してください。

## 対象
$ARGUMENTS

## 手順
1. 指定された指摘番号（例: #3, #1,#4）の内容を確認する。番号が指定されていない場合はすべての指摘を対象とする
2. 各指摘の修正案に従い、文書を修正する
3. 表記揺れの指摘については、推奨された表記に文書全体を統一する（指摘箇所以外にも同じ揺れがないか確認する）
4. 修正内容を報告する

## 注意
- 修正案をそのまま適用することを基本とするが、前後の文脈に合わない場合は調整する
- 表記揺れの統一では、指摘された箇所だけでなく文書全体を対象に統一すること
- 技術原稿の修正は `/proofread` が定義する「文章規範（整形・表記）」に沿わせること（一文ごと改行、ダッシュ・中黒の不使用、太字と「」の使い分けなど）
- 修正前後で次の4点を変えないこと。主張（何を言っているか）、比重（何を主とし何を従とするか）、言い切りの強さ（断定・推量・可能性）、文の働き（評価・説明・依頼・予定）。修正案がこのいずれかを動かす場合は、文脈に合わせて調整するか未対応に回す
- 元の文と前後にない動作主・名詞・条件・数値・例・術語を足さないこと。指示語を名詞に戻す、省かれた目的語を補うのは、指す先が前後の文に明示されているときだけとする。補えない情報は本文で創作せず「書き手に確かめたい点」に回す
- 長い文を分けるのは、前後の関係（手段・理由・順序・対比）を後ろの文の接続表現（「そのため」「一方で」など）で残せるときだけとする。目的や理由が文末の結論にかかる文（「〜するために〜します」）は、分けると向きが変わるので分けない
- ダッシュを外して前後を一文につなぐとき、前にある理由や条件（「〜ため」「〜なら」）のかかる範囲が後ろまで広がるなら二文に分ける
- 文末をそろえるときは、立場に合わない文末だけを直す。強さを上げない（勧めを「〜しなければならない」にしない）、主語を足さない、文をつなげて同じ文末の数を減らさない
- 修正は一回で済ませる。指摘を消すためだけに言い換えを重ねない
- 修正後に元の文と見比べ、元にない語が増えていないか、必要な語や前提が消えていないか、文末の種類が意図せず変わっていないか、箇条書きを地の文にした際に評価や義務（「〜が大切です」「〜する必要があります」）が足されていないかを確かめる

## 報告フォーマット
報告は Markdown として表示される。各指摘は下の形のとおり `- #番号 …` の項目の下に各欄を入れ子の箇条書きで並べ、区切り線（`---`）は使わない（文の直後の `---` は直前の行を見出しに変え、箇条書きにしない行は改行が消えて一行につながるため）。

### 修正内容

- #番号 カテゴリ（誤字脱字 / 表記揺れ / 句読点・記号 / 不自然な日本語 / 読みにくい文 / 段落・構成 / 文体・文末 / 文章規範（整形・表記））
  - 箇所: `file:line`
  - 変更前: 修正前のテキスト
  - 変更後: 修正後のテキスト

### 未対応の指摘
修正を見送った指摘があれば、番号と理由を記載する。

### 書き手に確かめたい点
修正に必要な情報が文書から読み取れなかった点、接続先や文書の立場を決めきれなかった点があれば、最大3点まで問いの形で記載する。なければ見出しごと省く。
