直前の /xcheck の結果から、指定された指摘番号について修正してください。

## 対象
$ARGUMENTS

## 手順
1. 指定された指摘番号（例: #X3, #X1,#X4。接頭辞のない #3 も同じ指摘として扱う）の内容を確認する。番号が指定されていない場合はすべての矛盾・不整合を対象とする
2. 各指摘について、矛盾する2箇所のうちどちらに統一すべきか判断する
   - 文書の主旨や文脈から適切な方を選ぶ
   - 判断が難しい場合（どちらも妥当、または両方誤りの可能性がある場合）はユーザーに確認を取る
3. 統一先を決定したら、矛盾する箇所を修正する
4. 修正によって他の箇所に新たな矛盾が生じないか確認する
5. 修正内容を報告する

## 注意
- 直すのは、指摘された矛盾・不整合の箇所だけにする（7つの種別のどれも対象。内容の重複は片方を削るか、もう片方への参照に置き換える）。同じ文のほかの部分の主張・比重・言い切りの強さ・文の働きは変えない（言い切りの強さと文の働きが指す範囲は `/fix-proofread` の「意味を保つ」と同じ）
- 用語を統一するときも、引用文・台詞・書名や作品名・コードと識別子・仕様書や画面の項目名は原文のまま残す（コードの不整合を直すときの識別子はこの限りでない）
- 参照の不整合（「第3章で説明します」に対応する説明がない）は、参照の文を直すか消して解消する。対応する説明を本文に書き足すのは、その内容が文書のほかの箇所から決まるときだけにする
- 技術原稿で書き換えた文は、`/proofread` と `/advise` の文章規範に沿わせる

## 報告フォーマット
報告は Markdown として表示される。各指摘は下の形のとおり `- #X番号 …` の項目の下に各欄を入れ子の箇条書きで並べ、区切り線（`---`）は使わない（文の直後の `---` は直前の行を見出しに変え、箇条書きにしない行は改行が消えて一行につながるため）。

### 修正内容

- #X番号 種別
  - 統一方針: どちらに統一したか、またはどう解消したかの説明
  - 修正箇所: `file:line`
  - 変更前: 修正前のテキスト
  - 変更後: 修正後のテキスト

### 未対応の指摘
修正を見送った指摘があれば、番号と理由を記載する。
